Code Sleuth gives you a helpful list of what's worth doing before your code is public facing.

It's a list to get you started. Every project's bar is its own, and the call is yours.

  • It runs on your machine and never writes to your repository.
  • Twenty-four checks read your files and your git history.
  • You get a checklist, and cards ready to file for what needs work.

What it looks for

What you'd like to tidy first

Tokens and keys in the files and the history, .env and key files, paths from somebody's machine, large files, notes-to-self, and the names on your own deny list. Secrets stay masked everywhere it reports them, like ghp_****9f.

The welcome a stranger gets

A README that says how to start, a license, a contributing guide, a code of conduct, a security policy, a changelog, and issue and pull request templates. Your repository is often how people first meet your work.

The parts that keep it running

CI, tests in CI, workflow permissions, a lockfile, dependency updates, dependency licenses, known advisories, and dependencies a major version behind. The dependency checks read npm projects today; for other ecosystems they say they weren't investigated.

What comes back

  • Nothing on the checklist stands in the way.

  • Only loose ends do.

  • A smoking gun does.

A verdict is a finding by this checklist, not permission. READY doesn't mean a repository is safe to publish, and a check that can't run says so rather than reading clean. What the verdict means and doesn't.

From a run on a small sample project in Code Sleuth's own tests.

Try it

In the repository you want to know about, with Node 24 and git 2.31 or newer:

npx github:johnfrog76/code-sleuth --goal public

It isn't on npm yet, so this runs it straight from GitHub. The case file goes to your own cases folder, never into the repository. Without --polish, the only calls it makes are the dependency lookups; it names them first, and --offline turns them off.

Two extras, neither required: --polish rewords each card with a small model and your own API key, and --toolkit files the cards in ToolKit once you say yes.

The quick start walks through a first case, or an install from a clone.
