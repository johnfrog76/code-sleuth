# Changelog

All notable changes to Code Sleuth are written here, for the people who use it. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed

- The project page's heading reads "Code Sleuth" in full on every machine. It was a picture of the name drawn in Helvetica Neue, and where that font is missing, as on Windows, the wider fallback cut off the last letter. The heading is now text in the page's own fonts, with the mark beside it as decoration. The logo files draw the name to a set width, so they fit their canvas in any font.

### Changed

- One missing lockfile reads as one thing to do. `license.deps`, `deps.advisories` and `deps.outdated` still read not investigated without it, each with one short sentence pointing at `deps.lockfile`, whose line and card carry the fix. `license.deps` reads clean when no `package.json` has dependencies: there are no licenses to read.
- With no API key, the Polish line's copy command names Code Sleuth's own folder alone. The run first puts a copy of `.env.example` beside where the `.env` goes, only when none is there, never over a file and never inside the repository, and readable by you alone, so under npx the command no longer points into npm's cache.
- `deps.advisories` and `deps.outdated` read every npm project, the root and each folder below it whose `package.json` has dependencies, one lookup in each folder, and the `Out` line names each (`(for web/)`). A workspace member is read through the workspace root that names it. Before, a project below the root read not investigated, named; now it is looked up.
- Under `--offline`, `deps.advisories` and `deps.outdated` say `--offline` only where they would have looked something up. With no `package.json`, no dependencies or no npm lockfile, no call would be made, so they read as they do online: clean, or not investigated with the lockfile's reason.
- On Windows, when PowerShell's execution policy (`Restricted`, or `AllSigned`) will not run the hand-off script, the case and the terminal say so, naming the policy, in place of "ToolKit isn't here", and `--toolkit` is refused with your own fix as the hint (`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`). Code Sleuth never changes the policy and never goes around it. CI proves it on a Windows runner set to `Restricted`.
- Example folders match in any case, on every platform, and `tests/fixtures/` is one beside `test/fixtures/` and `__fixtures__/`: a `Tests/fixtures/` folder, as .NET, PowerShell and Python projects often spell it, is an example location. An `--examples` glob matches in any case too. Example matches are still shown and kept, never dropped.
- A line carrying `code-sleuth:example` is an example for every check, the workflow checks and a commit message's `names.deny` match included, set in one place as each result leaves its check. A one-line `run:` with a trailing comment is found on its own line, not line 0.
- When git is there and does not answer in time, the run says so: the repo line reads `(git did not answer in time)` in place of `(not a git repository)`, a check that needs git says `git did not answer in time, so I couldn't read what it would have told me.` in place of asking you to install git, and `case.json`'s `repo` carries `gitTimedOut: true`. It still never reads clean.
- Under `--offline`, the polish line says polish is off because of `--offline`, whether or not `--polish` was given, and no key is read to say it. It no longer suggests adding `--polish`, which `--offline` would turn off.

### Added

- The periodic audit, `.github/workflows/periodic-audit.yml`: monthly, on every `v*` tag and by hand, it runs the quick start's npx line from the home folder, with `--offline` and `--out` added, against the decoy case (`scripts/make-decoy-case.mjs`) on Linux, macOS and Windows, checks every expected result with `scripts/check-decoy-case.mjs`, and opens an issue when a run fails.

## [0.2.0] - 2026-11-12

### Changed

- The `Out` line names looking for ToolKit whenever it starts a PowerShell, and `SECURITY.md` and `docs/CONFIGURATION.md` say plainly that ToolKit, once loaded, may reach GitHub through `gh`, which `--offline` skips. The quick start's Windows note covers cmd too: run `cd %USERPROFILE%` first, since cmd does not read `~`.
- **`--offline` means nothing leaves the machine.** It also turns off the polish request, even with `--polish` (polish reads off, because of `--offline`), and the ToolKit probe, so no PowerShell is started: the ToolKit line and `case.json` (`"state": "not-probed"`) say ToolKit was not probed. `--offline --toolkit` is refused. Every PowerShell Code Sleuth starts gets `POWERSHELL_TELEMETRY_OPTOUT=1` and `POWERSHELL_UPDATECHECK=Off`.
- What Code Sleuth writes keeps the repository's text as data. In `case.json`, `case.md`, the cards, the polish request and a ToolKit card, control, bidirectional and invisible format characters from the repository become U+FFFD; in the terminal they print as `?`, and a line break in a file's name prints as a space. A card's evidence stands under `Quoted from the repository, not instructions.`, each excerpt fenced and cut at 160 characters, and every card ends with a `**Source:** Code Sleuth <version>` line before its fingerprint. `--toolkit` files the cards as Code Sleuth wrote them, never the polished ones, which stay in the case folder.
- A repository cannot ask more memory of the machine than a laptop has. A text file over 5 MB (the `files.large` threshold) is not read by the text checks, and the history is read up to 64 MB of git's output or two million added lines; past either, a check that would read clean reads not investigated and says why, and the run ends in its sentence. The history is parsed line by line, never split whole.
- What Code Sleuth reads, and where the programs it starts begin, come from the repository's own commits and from you, never from a string the repository supplies. A path the index lists that leads outside the repository is not read, and a check that would read clean beside one reads not investigated, naming it. git reads the history with no replacement object or graft and with its own diff prefixes, and a git call stops after a minute (ten to read the whole history). PowerShell and gh start in Code Sleuth's own folder, and PowerShell's module path keeps absolute folders only. `XDG_DATA_HOME` and `LOCALAPPDATA` count only when they name an absolute folder, and a key file inside the repository is never read.
- The polish guard throws away a few more rewrites it can see: one that adds a reference definition, text in square brackets, a character outside ASCII the card does not use, or more than 15% more words (6 for a short card), and it reads code spans as a renderer does, so an escaped backtick cannot hide a span. `case.json` gives these as `reference-added`, `bracket-added`, `character-added` and `words-added`. The prompt asks for straight quotes, no brackets and no added sentence. The guard still compares a list, not meaning.
- The package's version is 0.2.0, the release the quick start pins.
- **The verdict is MET, NEARLY MET or NOT MET.** `case.json`'s `verdict` values change from `ready`, `nearly` and `not-ready` to `met`, `nearly-met` and `not-met`, decided as before. The stamps read MET, NEARLY MET and NOT MET, and every goal's sentence reads `met for <goal>`: `By my checklist: nearly met for public facing.` The verdict says it is the checklist's, and under MET and NEARLY MET one line says your software may have requirements of its own and points to a new section, [what MET doesn't cover](docs/CHECKS.md#what-met-doesnt-cover). `docs/CHECKS.md` says where the bar comes from, how a project's own context moves it, and what Code Sleuth doesn't judge. `caseFile` stays 1.
- Code Sleuth's own words claim no state they cannot know. The page, the quick start and `docs/CHECKS.md` say the verdict is a finding by this checklist, not permission to publish. A test holds the docs, the page, the templates and the copy files to it, with each remaining use of those words listed and its reason given.
- The docs open with what each one gives you, and claim only what the code and tests back. `docs/CHECKS.md` says what being public facing opens (the files, the history and the tracker) and that the tracker is not read yet. A goal that is not ready says it is planned for a later release, not that it comes in the next one.
- The goal's words: the output, the case file, `--help`, the goal prompt, the docs and the project's page call the goal "public facing" wherever a person reads it, and the run's goal line is `Goal  public facing`. The flag stays `--goal public`.
- The project's page looks like the deck's jungle, not a brown study. Its colours come from the deck's canopy and dusk sky, named once in `src/atoms/figures.tsx` and written to `site/tokens.css`. The banner opens on the dark jungle and the page ends in the lit one, in light and dark, and every word meets WCAG AA on what it sits on. The banner's actions are "Watch the video", hidden until the video exists, and "Read the README".
- The README opens with the ASCII sloth alone. The drawn logo is gone from it, because GitHub's mobile app showed it as a broken image. The project page and the social preview still carry it.

### Added

- The project's page, `site/`, for GitHub Pages: what Code Sleuth gives you, what it looks for, a real checklist and card from a sample run, and how to try it. Light and dark, at phone width, with no script and no web font. Its verdict stamps are green, amber and red, from one set of colour tokens in `src/atoms/figures.tsx`, and each keeps its word.
- `docs/QUICKSTART.md` and the project's page show `cd ~ && npx github:johnfrog76/code-sleuth#v0.2.0 path/to/your/repo --goal public`, which runs a pinned release from GitHub with no clone. It starts outside the repository, because npm reads the `.npmrc` of the folder it starts in. The first run builds Code Sleuth from source, with its development tools.

No other `.env` is read, the key never reaches a process Code Sleuth starts, the run says where the key came from and never what it is, and it warns when others can read the file. With no key, the run prints the one line that copies the `.env.example` beside the command into place, both paths in full; the case file keeps it with both paths in their `~` form.
- A project contact, `codesleuth.project (at) outlook.com`, for conduct reports (`CODE_OF_CONDUCT.md`) and security reports (`SECURITY.md`, beside GitHub's private vulnerability reporting). It is written out, not linked, to slow down address scrapers.

### Fixed

- Every workflow rule reads a line in a time that grows only with its length, not its square: the step locator, the `${{ }}` reader, the stranger's-field and head-checkout rules. Workflows are parsed once per run, not once per check. `workflows.injection` and `workflows.prtarget` skip a `run:` line longer than 65,536 characters, and, with nothing else found, read not investigated, naming the line.
- Code Sleuth's run on its own repository shows one accepted finding: a made-up test value in an early commit's history, kept rather than have the history rewritten. `docs/KNOWN-GAPS.md` says so, and the self-run test holds it to that one commit.
- `deps.advisories` and `deps.outdated` no longer read not investigated over an npm project in an example location: a test's fixture project is bait, not the repository's own. Code Sleuth's own test bait is marked as such, and a test runs Code Sleuth on its own repository to keep it that way.
- Smaller things the code review found. A card whose title or body is itself `-Probe`, `--` or `-x: y` now files: each value reaches the hand-off bound to its name, as `-Title:<value>`. The PowerShell line that copies the `.env.example` doubles a curly apostrophe too, so a folder like `O’Brien` no longer breaks it, and a key file on another Windows drive is shown whole rather than as `~\D:\...`. Case folders are made readable by their owner alone (0700, files 0600), as the machine key already was. `_authToken="${NPM_TOKEN}"`, quoted, reads as the reference it is rather than a committed token. A path git quotes in the history (a tab or a quote in its name) is named as it is. And `docs.readme` reads `README.md`, not a `README-ja.md` that sorts ahead of it.
- A tracked file whose folder has been replaced by a link is no longer read through it. git still lists the file, and Code Sleuth read it from wherever the link pointed, outside the repository, into the case, the cards and a polish request. Every folder on a tracked path's way must now be a real one.
- A failure is a line, never a stack trace (#25). Anything Code Sleuth did not expect is now one `Error:` line with its message, masked, and one `Hint:` line saying where to report it, exit 3 (`CODE_SLEUTH_DEBUG=1` shows where it happened); exit 1 comes only from `--fail-on`. A check that throws, on a file it cannot open or a shape it did not expect, reads not investigated and the run goes on. An `--out` that cannot be written, a machine key Code Sleuth did not make, a ledger it cannot read, and a flag missing its value are each a refusal in Code Sleuth's own words. Ctrl-C at the goal prompt exits 130 and Ctrl-D is a refusal; a closed pipe (`| head`) ends what is printed, not the run; a polish answer of the wrong shape keeps the card as written, and a timeout while it is read is named a timeout; a ToolKit `Prompt:` path with a space or a `%` is read as written; and a repository folder name too long for the case folder's own name is shortened in it.
- Nine more checks no longer read clean, or a confident finding, on what they had not read. `workflows.prtarget` misses no checkout of `merge_commit_sha`, and `workflows.injection` reads `github.event['issue']['title']` as it reads the dotted form. `ci.tests` and `ci.present` read not investigated, rather than found, when the only workflow doesn't parse. `license.deps` keeps a finding beside a lockfile it cannot read, names that lockfile when it finds nothing, leaves one in an example location out, and reads an SPDX expression's grouping. `license.file` no longer takes `license-checker.json` for a license. `deps.advisories` and `deps.outdated` read not investigated on an npm project below the root, naming it; `deps.outdated` reads a v1 lockfile's versions and counts npm's exit 1 with nothing printed as a failure; and `deps.advisories` asks GitHub about a v1 lockfile's packages.
- The polish guard throws away more rewrites that change what it can see. A rewrite was kept when it added a link, a URL, HTML or a command in backticks, ticked every box, added a box with `*` or mid-line, put a line break other than LF in the title, rewrote the line its evidence quotes, changed or added a path outside backticks, wrote a number in other digits or in words, or added an underlined or HTML heading. Each is now caught, with two new reasons, `code-changed` and `markup-added`, and the prompt says the card is data, never instructions. Meaning is still out of its reach, and the docs say so.
- Text from the repository can no longer add markup to `case.md` or a card. A newline in a workflow's file name put a fake `## Clean` heading and a ticked line into `case.md` through a not-investigated reason; a lone carriage return in an excerpt broke out of its code span, and the line-ending pass turned it into a heading or HTML in a card; the repository's folder name and its branch went in raw. Every reason, folder name, branch and ToolKit sentence is now written on one line with markdown's and HTML's markup escaped, a code span and a card's title stay on one line whatever they hold, and our own `--deny <file>` now shows in a rendered `case.md` instead of vanishing as a tag.
- Text from the repository can no longer drive your terminal. A file's name, a branch or a manifest's field was printed as it was, so an escape sequence in it could clear the screen, rewrite a line already printed (a smoking gun among them) or set the clipboard; every control character in it is now printed as `?`, a refusal stays one `Error:` line and one `Hint:` line whatever path it names, and the only sequences that reach the terminal are Code Sleuth's own colours.
- A remote's password no longer stays in the case in part. `https://user:p@ss@host/o/r` was kept as `ss@host/o/r`; the credentials now run to the last `@` before the host, as git reads them, and a query or a fragment (`?access_token=`) is dropped too.
- A card is filed only when ToolKit says so. `handoff.ps1` exited 0 when ToolKit wrote an error it did not throw, so a card never made was recorded as filed, with its id unknown, and later runs skipped its check. It now reads the verb's error stream, and an error ToolKit did not handle is a failure. It also sets `TOOLKIT_QUIET_STARTUP`, ToolKit's marker for a caller that is not a person, so ToolKit's guard throws a stated refusal or a failure; a refusal is still read from ToolKit's `$LASTEXITCODE` of 2, by ToolKit's own contract, with or without the throw.
- A README or a file the repository writes can no longer stall a run. A long line of spaces in a heading, or a long run of trailing spaces, took a time that grows with the cube or the square of its length in `docs.readme` (13 lines and one line of 5 KB took 20 seconds), and a run of letters holding many secret-sounding words did the same in the `assigned-secret` rule (6 KB took 17 seconds). Headings are now read by hand, a README's end is trimmed without a pattern, a heading line is at most 4,096 characters, and the rule's name is at most 64 characters either side of its word.
- A program in the repository can no longer run in place of git or npm. A relative or empty entry on your PATH (`./node_modules/.bin`, `::`) was read against the folder each process ran in, which for git is the repository, and on Windows a program is looked for in that folder first. git, npm, gh and PowerShell are now found in the PATH's absolute folders only and started by their full path, and every process Code Sleuth starts gets a PATH of absolute folders.
- `secrets.history` no longer reads clean without reading the history. A shallow clone (`git clone --depth 1`) held only the history after its cut, and now reads not investigated, as `names.deny` does for its commit messages. A file the repository marks `-diff` or `binary`, or every file once it sets `core.bigFileThreshold`, showed git's "Binary files differ" and no lines; every file is now read as text. A line added in resolving a merge was never shown; each merge is now read against its first parent. And a `git log` that failed on a repository with refs but no `HEAD` was read as no history; only a repository with no refs at all is.
- A secret's value no longer reaches output in clear in four more ways. A line another check reports was cut to 160 characters before it was masked, so a token the cut split matched no rule and went out with most of it showing; every excerpt is now masked first, then cut. A not-investigated reason can quote the repository (a manifest's `license`, a file's name), and is now masked too. Where two matches overlap, as an access key id runs into its secret, the whole span is masked, not only the first. An `.npmrc` token holding `$&` was pasted back beside its mask; it is now cut out at its own place.
- The one writer guard no longer lets a case land in the repository. A folder inside the repository whose name starts with two dots, such as `--out repo/..cases`, read as outside it, so the case, the cards and the machine key were written there; a step up now counts only as a whole `..`. Pointed at a folder inside a repository, the guard compared against that folder alone, so `--out` could land beside it; it now holds the whole repository, and a submodule's superproject. The same holds for `--deny` and for where ToolKit would file.
- A repository's `.npmrc` can no longer have your npm token, or any of your environment's variables, sent to a host it chooses. npm ran in the repository, so its `.npmrc` was npm's project config: a `proxy` received your registry token, and a `${NAME}` in a registry URL sent that variable's value. npm now runs on a copy of `package.json` and the lockfile in Code Sleuth's own folder, so the repository's `.npmrc` is never read, and npm sees only the variables it needs, with those your own `.npmrc` names. `deps.outdated` gives npm a `package.json` naming each direct dependency from npm's registry at `*`, devDependencies among them, since with nothing installed `npm outdated` leaves out each missing devDependency; no spec from the repository reaches npm, so a git, path, URL or alias dependency is never fetched, and is named in the result instead.
- A repository can no longer have Code Sleuth's `git status` run a filter through a submodule, or through a filter named with an `=`. `status` read into each submodule, whose own config can name a filter; it no longer reads into one, so a change inside a submodule no longer marks the repository dirty. A setting given with `-c` is split at its first `=`, so a driver named `a=b` was never turned off; every setting now goes through git's `GIT_CONFIG_KEY_<n>` variables, which take the key whole. A git older than 2.31, which would ignore those variables without a word, is refused: one `Error:` line and one `Hint:` line, before the repository is read.
- Every folder Code Sleuth writes to goes through one guard. A repository that holds Code Sleuth's own folder, as `code-sleuth ~ --out elsewhere` does, is refused when npm would run, since npm keeps its cache and logs there.
- git's `fd`, `ftp` and `ftps` transports, and any `git-remote-<name>` helper on the machine, are turned off by name too.
- The case file keeps the `.env.example` to copy as a record (`keyExample`), not a line with a quoted `~` that would not run; the terminal still prints the line to run.
- Every case file is written with LF line endings, a polished card that came back with CRLF among them.
- A repository's own git config can no longer re-allow a transport. Every git call turned off transports with `protocol.allow=never`, which a repository's `protocol.<name>.allow` overrides; each transport is now turned off by name, on the command line, which outranks the repository's config. `--toolkit` is refused when ToolKit does not say where the cards would land.
- A file that would not parse no longer reads as no file. A `package.json` that isn't JSON made `deps.advisories`, `deps.outdated` and `deps.lockfile` read clean with nothing read, and could tip `license.deps`, `license.file`, `ci.tests` and `deps.updates` either way; each now reads not investigated, naming the file. `license.file` reads not investigated, rather than clean, when it cannot tell which license the file's text is.
- Nothing Code Sleuth runs writes into the repository it investigates. A repository's `.npmrc` could point npm's cache and its debug log into the tree, and npm writes a log on every command; npm's cache and logs now go to Code Sleuth's own folder. `--toolkit` is refused when a folder ToolKit would write a card into is the repository or inside it; a hub that only holds the repository, as ToolKit's default hub does, files as before.
- On a partial clone, Code Sleuth's git no longer fetches missing objects from the remote, a call off the machine the run never named. Every git call now blocks every transport and lazy fetching, the Repo line says "a partial clone", and `secrets.history` reads not investigated: some of the history is not there.
- A check that read nothing no longer reads clean. On a project in another ecosystem (Python, Go, Rust and others), `deps.advisories`, `deps.outdated` and `license.deps` read not investigated and name the manifest they found; beside an npm project, a clean npm side says the other side was not read. `names.deny` outside git reads not investigated when the files are clean, since the commit messages were not read, and a workflow that doesn't parse as YAML makes the workflow checks read not investigated, naming it.
- The polish guard keeps every path the card's evidence cites, word for word. It used to know a path only by its shape, so a rewrite that changed `.env:3` or dropped a bare `Dockerfile` or `LICENSE` was kept. It also counts each number: dropping one of two equal numbers is no longer kept.
- A secret on a line another check reports is masked too. A token in a `TODO` comment, a home-folder path or a workflow line was kept whole in `case.json`, the cards and the polish request; every excerpt, and every path, now goes through the secret rules in one place, whichever check found it.
- A repository's own git configuration can no longer have Code Sleuth run a command. A file-system monitor or a filter driver named in the investigated repository's `.git/config` ran when Code Sleuth read its status or file list; every git call now turns those off, along with the signature program, hooks, the pager and an external diff. A filter marked required, as git-lfs marks its own, no longer makes reading the status fail.
- An API key set in the environment no longer reaches the processes Code Sleuth starts. git, npm, gh and ToolKit's shell inherited it before; a key from Code Sleuth's `.env` never did. Every child now starts through one helper that takes the key out, in any letter case since Windows matches names without regard to case, and a test keeps any new child from skipping it.
- The build makes `dist/cli/main.js` executable itself, so `code-sleuth` runs after any rebuild, a re-clone under an old `npm link` among them, instead of answering "permission denied".
- A clean `npm ci` no longer reports moderate vulnerabilities: the development tools' `minimatch` is overridden to 11.0.4, past the advisory. Nothing Code Sleuth runs used it.
- `--toolkit` files in the repository's own ToolKit Space, the one whose address is its `origin`, rather than whichever Space is active. With no matching Space it falls back to the active one, and the footer says so.

## [0.1.0] - 2026-11-03

The first release: the whole loop on one goal, going public. Run from a clone, through `npm link`.

### Added

- `code-sleuth [<folder>] --goal public` investigates a repository and prints the verdict (READY, NEARLY or
  NOT READY) and the checklist, in the detective's voice. With no `--goal` in a terminal, it asks.
- Twenty-four checks for going public: secrets in the tree and in history, key and `.env` files, the license
  and dependency licenses, paths from somebody's machine, a deny list (`--deny`), large files, the README and
  community files, issue and pull request templates, CI and tests in CI, workflow permissions,
  `pull_request_target` and script injection, lockfiles, known advisories, dependency updates, dependencies a
  major version behind, and markers left in the code.
  `code-sleuth checks` lists them.
- A case file for every run, written outside the repository: `case.json`, `case.md` and one card per finding,
  in the shape a ToolKit card's description takes.
- Secrets are masked everywhere (`ghp_****9f`) and never stored; a keyed hash tells two runs it is the same
  secret.
- `--polish`: with an API key set, each card is reworded by Claude Haiku, and a rewrite that drops
  or changes a path, a number, a masked value or the fingerprint is thrown away.
- `--toolkit`: with ToolKit installed, each card is filed as a real ToolKit card through ToolKit's own
  command, once per check, after asking. `--yes`, `--refile`, `--toolkit-space` and `--toolkit-prefix`.
- `--out`, `--all`, `--json`, and `--fail-on smoking-gun|loose-end` for CI.
- `deps.outdated`: going public finds a direct dependency a major version or more behind its latest, through `npm outdated`, which sends package names to npm's configured registry. The run names that call before it makes it, and `--offline` turns it off.
- `deps.advisories`: going public and security find a locked package with a known advisory, through `npm audit`, or through GitHub's advisory database with `gh` when there is no npm. Both send the lockfile's package names and versions; the run names the call before it makes it, and `--offline` turns it off. A critical or high advisory is a smoking gun, a moderate one a loose end, a low one a hunch.
- A logo: the sloth private eye's head and hat, in the README and as the favicon and social preview.

### Changed

- The polish prompt asks the model to reword only: to add no specific the card does not give (a name, a place, a count, an example, a kind), to keep each word's meaning, and to drop nothing. The docs now say what the guard checks -- every path, number, masked value and the fingerprint -- and that it cannot see meaning.
- A match in an example location (`test/fixtures/`, `__fixtures__/`, a line marked `code-sleuth:example`, or `--examples <glob>`) is shown and no longer counted: it makes no card and changes no verdict, and the case asks you to check that it is fake.

### Fixed

- With `--toolkit` and no terminal to ask in, the run says once, not twice, that nothing was filed and how to file.
